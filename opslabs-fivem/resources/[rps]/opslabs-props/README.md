Access point: white matte body + glowing blue LED ring. Gateways: detailed front/back panel textures and glowing screens (emissive). All have embedded textures and collision (plastic / metal); fronts face the player when placed. No logos or text.

`/root/fivem/opslabs-dev/props-source/` holds the Blender files, the CodeWalker XML, previews and `build_ap.py` / `build_gateways.py` (the model is generated from code, so it can be rebuilt or tweaked — e.g. change the LED colour in `led_px`). It is not streamed.

Lights: every `<name>_on` model holds only the glowing lenses, with the same origin as its light, so it can be spawned on top at night (`build_lighting.py`).

Pipeline: Blender 4.2 + Sollumz 2.9 → CodeWalker XML → CodeWalker.Core (XmlMeta) → binary `.ydr` / `.ytyp`.

Mains kit is built by `/root/fivem/opslabs-dev/props-source/make_mains_tex.py` (textures) + `/root/fivem/opslabs-dev/props-source/build_mains.py` (previews: `/root/fivem/opslabs-dev/props-source/preview_mains_wall.png`, `preview_mains_desk.png`).

## Where the model sources live

The Blender files, texture generators (`make_*_tex.py`), build scripts (`build_*.py`), CodeWalker XML and preview renders
were moved out of the live server folder to **`/root/fivem/opslabs-dev/props-source/`** (they're never streamed and only
made the resource folder 90 MB bigger). Rebuild a kit from there with Blender 4.2 + Sollumz, convert the CWXML to binary
and copy the results into `stream/`, then register any new `.ytyp` in `fxmanifest.lua`.
